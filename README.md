# Vaultly - ваш персональный цифровой сейф

**Vaultly** - кроссплатформенное клиентское приложение для безопасного хранения и обмена файлами с полноценным end-to-end шифрованием, выполняемым непосредственно на устройстве пользователя. Приложение работает на **Android, iOS, Windows, macOS, Linux и в браузере (Web)** из единой кодовой базы Flutter.

> Текущий статус: **бета** (`1.0.13+15`).

---

## Возможности

- End-to-end шифрование файлов на устройстве (AES-256-GCM + RSA-2048 OAEP/SHA-256).
- Собственный формат контейнера `.shps` с цифровой подписью (SHA256withRSA).
- Управление пользовательскими и устройство-специфичными ключами; приватный ключ шифруется паролем пользователя (AES-GCM + PBKDF2).
- Стабильная идентификация устройства на основе аппаратных атрибутов (SHA-256 хэш).
- Полноценная поддержка Web через Web Crypto API.
- Локальный кэш расшифрованных файлов и «расшифровка на лету».
- Встроенный просмотр PDF, изображений, видео (`media_kit`).
- Обмен публичными ссылками и QR-кодами.
- Работа с мнемониками BIP-39, ключами BIP-32 и Ed25519 (через `pinenacl`, `bip39`, `bip32`, `ed25519_hd_key`).

## Криптографическая подсистема

Вся криптография выполняется **локально**. Приложение никогда не передаёт на сервер незашифрованные данные или приватные ключи.

### Генерация и управление ключами
- **`RsaKeyGeneratorWeb`** - генерация 2048-битных пар RSA (Web и нативные платформы).
- **`KeyManagerService` / `KeyManagerServiceWeb`** - централизованное управление ключами пользователя и устройства:
  - публичные ключи хранятся в открытом виде;
  - приватные ключи шифруются паролем пользователя (AES-GCM, ключ через PBKDF2 с солью);
  - расшифрованный приватный ключ кэшируется в памяти на время сессии;
  - отдельные пары ключей для **пользователя** (шифрование файлов) и для **устройства** (синхронизация зашифрованного пользовательского ключа через сервер).
- **`SecureStorageAdapter`** - адаптер над `flutter_secure_storage` и `shared_preferences`:
  - на iOS/Android/macOS/Windows/Linux - защищённое хранилище (Keychain/Keystore);
  - в Web - `SharedPreferences` (в рамках ограничений платформы).
- **`AuthLocalStorage`** - сохранение токенов доступа, информации о пользователе и пароля, зашифрованного мастер-ключом (AES-GCM).

### Формат SHPS
- **`ShirmpsHeader`** - структура заголовка контейнера `.shps`: метаданные, зашифрованный AES-ключ, IV, цифровая подпись.
- **`ShirmEncryptionService`** (нативный) и **`ShirmEncryptionServiceWeb`** (Web):
  1. генерация случайного AES-256 ключа и 12-байтного IV;
  2. шифрование данных AES-GCM (аутентифицированное шифрование);
  3. зашифрование AES-ключа публичным RSA-ключом получателя (OAEP, SHA-256);
  4. опциональная цифровая подпись исходных данных приватным ключом отправителя (SHA256withRSA);
  5. сборка контейнера: `[4 байта длины заголовка][JSON-заголовок][зашифрованные данные]`.
- **`ShirmDecryptionService` / `ShirmDecryptionServiceWeb`** - обратный процесс.

### Публичные файлы
- **`PublicFileDecryptionService`** - специализированная расшифровка для файлов с публичным доступом (когда сервер перешифровывает AES-ключ на публичный ключ запросившего пользователя).

## Локальный кэш

- **`LocalFileCache`** - сохраняет расшифрованные файлы в директории приложения (`file_cache`) для быстрого повторного доступа без повторной загрузки и расшифровки.
- Для каждого файла сохраняется оригинальное имя в отдельном `.name`.
- Поддерживаются очистка кэша и расчёт занимаемого объёма.
- В Web кэширование отключено (ограничения платформы).

---

## Расшифровка «на лету»

**`FileDecryptionService`** оркеструет процесс получения файла:
1. Проверка наличия в локальном кэше.
2. Загрузка `.shps`-контейнера с сервера (через `FileInterface`).
3. Определение типа файла (приватный/публичный).
4. Расшифровка с использованием приватного ключа пользователя (запрашивается пароль).
5. Сохранение расшифрованных данных в кэш.

---

## Уникальная идентификация устройства

**`DeviceIdGenerator`** формирует стабильный идентификатор устройства на основе аппаратных и системных атрибутов (Android ID, `identifierForVendor` на iOS, machine ID на Linux и т.д.) с хэшированием SHA-256. Используется для регистрации устройства на сервере и управления ключами синхронизации.

## Поддержка Web

Для браузера реализованы отдельные сервисы на базе `package:webcrypto` (Web Crypto API) вместо `pointycastle`. Это обеспечивает высокую производительность криптографических операций и соответствие стандартам безопасности браузеров.

---

## Принципы безопасности клиента

- Приватные ключи **никогда не покидают устройство в открытом виде**.
- Все криптографические операции выполняются локально.
- Пароль пользователя используется только для расшифровки локального приватного ключа; сервер его не получает.
- Кэшированные файлы хранятся в открытом виде, но доступ к ним ограничен файловой системой приложения.
- Идентификатор устройства не содержит персональных данных - только хэш системных атрибутов.

## Сборка и запуск

### Требования
- Flutter SDK с Dart `^3.10.9`
- Настроенное окружение под целевую платформу (Android Studio / Xcode / Visual Studio / Linux-toolchain)

### Установка
```bash
git clone <repository-url>
cd vaulth_app
flutter pub get
```

### Запуск
```bash
# Android / iOS / Desktop
flutter run

# Web
flutter run -d chrome
```

### Сборка релиза
```bash
flutter build apk --release         # Android
flutter build ios --release         # iOS
flutter build windows --release     # Windows
flutter build macos --release       # macOS
flutter build linux --release       # Linux
flutter build web --release         # Web
```

### Иконки приложения
Генерация иконок под все платформы выполняется через `icons_launcher` (см. секцию `icons_launcher` в `pubspec.yaml`):
```bash
dart run icons_launcher:create
```
